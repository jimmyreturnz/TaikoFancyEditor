# Taiko Fancy Arranger

> 英語版は [README.md](README.md) を参照してください。

**ビジュアルパターンアレンジャーを内蔵した osu!taiko エディター。**

Taiko Fancy Arrangerは、osu!taikoのノーツを手作業で1つずつ置くことなく、テキスト・図形・数式・絵・らせんといった視覚的なパターンへ変換するツールとして始まりました。バージョン2.0.0でエディターへと成長し、osu!のSongsフォルダを閲覧して難易度を開き、ノーツを編集し、スクロールベロシティ（SV）を編集し、osu!が描画する通りにチャートをプレビューしつつ、望めばノーツをパターンに配置することもできるようになりました。バージョン3.0.0では、ノーツではなくタイミングポイントから作られるフェイクスライダー・小節線トリック・極端なSV効果、つまりosu!taikoマッパーが作る「ギミック」専用のエディターを追加しています。バージョン3.2.0では楽曲再生を作り直して低速練習でも位置がずれないようにし、ノーツを描画するすべてのビューでお使いのosu!スキンを使えるようにしました。

どのビートマップも、常にプレイ可能なosu!ビートマップのままです。エディターがモデル化していないセクション——ストーリーボード、ブレイク、色、エディターのブックマーク——は、保存時にバイト単位でそのまま引き継がれます。

> **現行リリース:** v3.3.3
> **プラットフォーム:** Windows x64
> **作者:** [jimmyreturnz](https://osu.ppy.sh/users/11306153)

もともとの着想は、maruaki101との何気ない会話から生まれました。他にもAlchyrのランク譜面 *13 Stairs* と *Helios* からインスピレーションを受けています。これらは通常とは異なるノーツ配置で視覚的な表現を作り出しています。ぜひ[こちら](https://osu.ppy.sh/beatmapsets/1093671#taiko/3819326)をチェックしてみてください。

## 3.2.0の新機能

このリリースでは楽曲再生を作り直し、ノーツを描画するすべてのビューでお使いのosu!スキンを使えるようにしました。

- **楽曲再生の作り直し。** アプリ自身が音声をデコードし、サウンドカードを直接駆動します。速度変更で再生位置がずれなくなり（従来のバックエンドは0.25倍→1.0倍の切り替えで114ms分の曲時間を失っていました）、低速再生でも音程は変わらず、再生位置は実際にデバイスから出ていくサンプルに追従します。
- **音楽オフセットの調整。** **設定 → オーディオ**でクリック音に合わせて叩くと、アプリ自身の出力オフセットが決まります。譜面自体のオフセットには一切触れません。
- **スキン。** osu!のSkinsフォルダから太鼓スキンを選ぶと、ノーツの絵・連打の各パーツ・ヒットサウンドが、ゲームプレイプレビューとエディターのタイムラインレイヤーの両方に適用されます。要素ごとに、無いものは内蔵の描画に戻ります。
- **ゲームプレイプレビューがプレイフィールドに。** スキンのバー・スクロール背景・小節線・判定位置を、osu!自身の比率で描画します。ノーツは判定位置に達すると消え、連打は通過し、キアイでは拍ごとに光ります。
- **ノーツの不透明度。** エディター各レイヤーでノーツをどれだけ濃く描くかを設定でき、スナップグリッドの見やすさとノーツの見やすさを調整できます。
- **意味を持つようになった音量。** 「キアイとサウンド音量」レイヤーの数値が、実際のドン・カツの音量を決めるようになりました。このレイヤーの線は上下にしか動かず、小節線レイヤーではドンとカツを別々に左右対称にできます。
- **主な修正。** 高速スクロール時の耳をつんざくヒットサウンドの暴発、高BPM区間でシークが後退する問題、設定ウィンドウのスクロールが背後のエディターに漏れる問題、ギミックページのスクロールバーが効かない問題を修正しました。

詳細: [`docs/releases/v3.2.0.md`](docs/releases/v3.2.0.md)

## 3.0.0の新機能

このリリースでは、ノーツではなくタイミングポイントから作られる視覚効果——ギミック——のための4つ目のエディターページに加えて、ヒットサウンドと、エディター全体にわたる精度面の修正の数々を追加しています。

- **ギミックエディターページ。** 1つの難易度の上に6層が重なります。通常のチャート、フェイクスライダー、小節線ギミック、そしてその3つそれぞれのSVレイヤーです。ページに入ると、その難易度をそのまま編集するか新しい `[Gimmick]` 難易度にコピーするかを一度だけ尋ねられ、ベースタイミングのスナップショットを取得します。これにより、何千行もの60000 BPMのギミック行がファイルに積み重なっても、グリッドがその場に留まり続けます。
- **フェイクスライダーとシャイニーノーツ。** フェイクスライダー、シャイニーノーツ、一定間隔で並ぶフェイクスライダーの連続、チャート自身のノーツをギミック構造へ変換する機能、ドラッグした範囲へのキアイ塗りといった専用ツールを用意しています。
- **小節線ギミック。** 赤線から描かれるノーツを、ノーツを中心に対称配置するか後方に続けるかで作れます。ミリ秒数またはビートグリッドを基準に、BPMランプも含めて範囲を赤線で埋める関数ツール付きです。
- **構造ごとのSV。** チャート・フェイクスライダー・小節線の各レイヤーは、それぞれ自分の構造の緑線だけを持つ専用のSVレイヤーを持ちます。インデックス基準のコピー＆ペーストと、ジェネレーターに追加された振動カーブが使えます。
- **ヒットサウンド。** `assets/se/` に同梱されたサンプル——ドン、カッ、大ドン、大カッ——を使い、再生中にノーツが音を鳴らします。新しいオーディオ設定ページに、ヒットサウンドの有効・無効、音量、レイテンシーオフセット、音楽の音量がまとまっています。
- **ミリ秒単位の正確な編集。** グリッド、再生ヘッド、あらゆる配置が、osu!の丸め方（0.5は切り上げ、Pythonは偶数丸め）に合わせて1ミリ秒単位で一致するようになりました。**Ctrl** を押しながらだと、スナップ設定に関わらず1ミリ秒精度で配置でき、ミリ秒の読み取り値もリアルタイムに表示されます。
- **どこでもキアイ。** キアイ区間はすべてのギミックレイヤーで半透明のオレンジ色の帯として描画され、生成されたタイミングポイントはそのセクションのキアイ状態を黙って終わらせるのではなく引き継ぐようになり、ゲームプレイビューアーのキアイフラッシュは画面上のすべてのノーツに届くようになりました。
- **細かな編集の改善。** スライダーとスピナーの終端を選択ツールでドラッグできるようになり、タイミングバー上での右クリックはドラッグ選択を終わらせずに再生位置をスクラブでき、拒否された操作は何も起きないのではなくトースト通知で知らせ、すべてのスピンボックスにピンク色の+/-ボタンが付きました。

詳細はすべて[`docs/DEVELOPMENT_PLAN.md`](docs/DEVELOPMENT_PLAN.md)にまとまっています。

## オーディオ設定

再生中、`assets/se/` に同梱されたヒットサウンドサンプルを使ってノーツが音を鳴らします。ドン・カッ・大ドン・大カッにはそれぞれ専用のサンプルがあります。音が鳴るのはドンとカッだけで、フェイクスライダーと小節線ギミックは無音のままです。

**オーディオ** 設定ページには、ヒットサウンドの有効・無効と音量、ミリ秒単位のレイテンシーオフセット、そして以前はUIすらなかった音楽の音量がまとまっています。

### 低速再生

25%・50%・75%でも **元の音程を保ちます**。レコードを遅く回すような減速ではなくタイムストレッチを行うため、4分の1の速度でも本来の楽器の音のまま聞こえます。osu!のエディター自体と同じ方式です。

速度を切り替えても再生は途切れません。すでにスピーカーに向かっている音声は旧速度のまま再生され、その後から新しい速度になるので、空白も跳びも、切り替えによるずれも生じません。

再生位置は進捗通知ではなく、実際にオーディオデバイスから出ていくサンプルから求めているため、どの速度でも音楽とずれません。

オーディオ設定ページの **音楽オフセット (ms)** で、音が耳に届くタイミングに再生位置を合わせられます。適切な値はデバイスとドライバー次第なので、初期値は0です。聞こえる音より譜面が早く見える場合は値を上げてください。実時間で測るため、どの再生速度でも同じ値が有効です。

## 初回起動

1. **言語を選択します。** EnglishまたはJapanese（日本語）。この画面はあなたがどの言語を読むか判断できない唯一の画面であるため、意図的に翻訳されていません。
2. **osu!のSongsフォルダを選択します。** `%LOCALAPPDATA%/osu!/Songs` が存在する場合はあらかじめ入力されています。フォルダは記憶され、ライブラリページから後で変更できます。
3. **スキャンを待ちます。** 初回のスキャンはすべての`.osu`ファイルを一度読み込むため、コレクションが大きいと時間がかかります。処理は分割して実行されるため、ウィンドウは応答し続けます。2回目以降の起動では、検証前にキャッシュされたリストが表示されます。

フォルダ選択をキャンセルすると、行き止まりではなく**フォルダを変更**ボタン付きの空のライブラリになり、次回の起動時に再びセットアップが提示されます。

## 曲ライブラリ

ライブラリページが入り口です。

- 左側: `アーティスト - 曲名 · マッパー · 難易度数` として表示される曲一覧。
- 右側: 選択した曲の難易度一覧。
- 難易度をダブルクリックするか、**この難易度を編集**を押すと、エディターで開きます。

コントロール:

- **検索（Search）** — アーティスト、曲名、両方のUnicode表記、難易度名、作成者、タグを一度にマッチさせます。
- **グループ化** — なし、マッパー別、アーティスト別。
- **並び順** — A→Zまたは Z→A。これによりグループの順序も反転します。
- **原語のメタデータ** — ローマ字表記の代わりに`ArtistUnicode`/`TitleUnicode`を表示し、それが無い場合はマップが実際に持っている方にフォールバックします。

太鼓の譜面（`Mode: 1`）のみが一覧に表示されます。

## エディターページ

エディターページはビューを難易度ごとにまとめて縦に並べます。**+**（ビュー種類＋難易度）でビューを開きます。難易度を開くと、自動的にチャートビューとSVビューが与えられます。

ビューの種類:

| ビュー | 内容 |
|---|---|
| 譜面 | 上下の端に固定されたスナップグリッド付きの、時間軸上のノーツ |
| SVエディター | 赤・緑・黄色のタイミングラインと、実効SVグラフ |
| プレイビューアー | 読み取り専用のosu!taiko風プレビュー。オブジェクトはそれぞれのSVでスクロールする |
| 密度 | 白から黄色へのノーツ密度ヒートマップ |

プレイビューアーのキアイフラッシュは、キアイ開始時にたまたま画面内にあったノーツだけでなく、画面上のすべてのノーツに届きます。

ビューの上部には、ビートスナップ、統合された時間とパーセンテージの表示、タイミングバー（キアイ、ブックマーク、SV、BPM）、再生ボタンと再生速度ボタンがあります。スナップ分割数はページ全体で共通なので、すべてのビューが同じグリッド上に揃います。ズーム（`Ctrl+ホイール`）は難易度ごとで、その難易度のビュー間で共有されます。ドラッグ選択中にタイミングバーを右クリックすると、選択を終わらせずに再生位置をスクラブできます。

各ビューのUI要素: **閉じる**、**ロック**（読み取り専用）、右側の難易度名。

エディターが拒否する操作——たとえば違う種類のビューへの貼り付け——は、何も起きないのではなく一時的なトースト通知を表示します。

### ノート編集

ツールバーはページ下部にあり、フォーカスされているチャートビューに対して動作します。

```text
1  Select
2  Don
3  Kat
4  Slider
5  Spinner
6  New combo
```

- 左クリックでスナップされた時間に配置され、半透明のゴースト表示で配置先がプレビューされます。
- スライダーとスピナーは**クリックドラッグ**で長さを決めます。既存のものの右端付近を押すとリサイズでき、その後**選択**ツールで終端をドラッグすることもできます。
- **Shift**を押しているとノーツプレビューが即座にリサイズされ、離すと大ノーツ（フィニッシャー）やビッグスライダーが配置されます。
- 右クリックでカーソル下のノーツを削除、**Delete**で選択範囲全体を削除します。
- スピナーを除き、1ミリ秒につき1オブジェクトです。ノーツの上に配置すると、それを置き換える1回のUndo単位の操作になります。

### SV編集

SVビューがフォーカスされていると、ツールバーは次のようになります。

```text
1  Select
2  Green line
3  Function
```

- 赤線は継承なし（BPM）ポイント、緑線は継承あり（SV）ポイント、黄色は両方が同じミリ秒を共有していることを意味します。
- 緑線をクリックすると選択され、縦にドラッグするとSVが変わり、横にドラッグするとグリッドにスナップされた形でリタイミングされます。どちらの軸になるかは、クリック位置が値のドットにどれだけ近いかによります。
- 範囲をラバーバンド選択、`Ctrl+A`で表示中のすべて、`Delete`で削除。継承なしポイントはここでは削除されません。
- タイミングラインをダブルクリックすると、キアイまたはそのラインの小節線省略フラグが切り替わります。
- グラフは**実効**SVを表示します——両方存在する場合は緑が赤の上に重なり——固定の0.1x下限と自動スケーリングされる上限を持ちます。

**関数モード:** 範囲をドラッグしてから、初期倍率、最終倍率、位置オフセット、最初の小節線を省略するかどうか、スイープが最終BPMに対して相対的かどうかを選びます。7つのカーブがタイルとして提示され、それぞれ実際に入力した値通りのスイープを描画します。

```text
linear   sin in   sin out   exp1.3   exp1.6   true exp   sin
```

ポイントは既定では範囲内のノーツ上に生成されるか、Nスナップごとに生成されます。既定の−5msオフセットにより、そのノーツが来た時点で既にSVが効いていることが保証されます。生成したポイントがいくつであっても、それは1回のUndo単位です。

### ミリ秒精度

osu!は整数ミリ秒を保存する一方でビートグリッドは小数を扱うため、深いズームではオブジェクトが自分自身のグリッド線から視覚的にずれて見えることがありました。グリッド、再生ヘッド、あらゆる配置は、osu!の丸め方（0.5は切り上げ、Pythonは偶数丸め）に従って1つの整数ミリ秒に一致するようになりました。

**Ctrl**を押しながらだと、スナップ分割数に関わらず1ミリ秒精度で配置でき、各ビューの隅にガイドラインとミリ秒のリアルタイム読み取り値が表示されます。

Ctrl+C / Ctrl+V     Copy / paste notes or SV points, snapped on paste
Ctrl+S              Save every changed difficulty

未保存の変更を残したままエディターを離れようとすると、未保存の難易度が名前付きで一覧表示され、**保存**、**保存せずに続行**、**キャンセル**のいずれかを選べます。保存せずに続行しても、編集内容はセッション内に残ります——何も書き込まれず、何も破棄されません。

## ギミックエディターページ

osu!taikoにおける「ギミック」とは、ノーツではなくタイミングポイントから作られる視覚効果のことです。負の長さで描画されるだけで叩けないドラムロール（「フェイクスライダー」）、小節線から描かれるノーツ、そしてオブジェクトを画面上で動かすために使われる極端なBPM/SV値がこれにあたります。

ギミックページは、1つの難易度の上に6層を重ねます。通常のチャート、フェイクスライダーレイヤー、小節線ギミックレイヤー、そしてその3つそれぞれのSVレイヤーです。

ある難易度でこのページに入ると、その難易度をそのまま編集するか新しい`[Gimmick]`難易度にコピーするかを一度だけ尋ねられ、その答えは恒久的に記憶されます。またその瞬間に**ベースタイミングのスナップショット**を取得します。ギミックはファイルを60000 BPMの行で埋め尽くし、その一つひとつがスナップグリッドを崩壊させるため、グリッド、ホイールスクロール、BPMオーバーレイはすべて編集中のファイルではなくこのスナップショットから駆動されます——ギミックのタイミングポイントが積み重なっていっても、グリッドがカーソルの下で動くことはありません。

キアイ区間はすべてのレイヤーで半透明のオレンジ色の帯として描画されます。ギミックツールが生成するすべてのタイミングポイントは、それが位置するセクションのキアイ状態を、黙って終わらせるのではなく引き継ぎます。

### フェイクスライダーとシャイニーノーツ

フェイクスライダーレイヤーは、フェイクスライダーと「シャイニー」ノーツ——1ミリ秒に複数のフェイクスライダーを重ねたもので、ゲーム内ではノーツの横に明るい白い輝きとして表示されます——を配置します。この2つは位置で見分けられます。ノーツやラインの1ミリ秒後にあるオブジェクトはシャイニー、2ミリ秒後にあるものはフェイクスライダーです。このレイヤーは、ギミックのズームレベルではこの2つが1ピクセル列しか離れていないため、フェイクスライダーを上段、シャイニーを下段に、中央にスナップグリッドを挟んで2段に描画します。

ツール:

```text
Fake Slider
Don / Kat
Shiny
Multiple Fake Slider
Function
Convert Notes
Kiai
```

- **複数フェイクスライダー**は、設定した間隔でフェイクスライダーの連続をワンクリックで書き込みます。
- **関数**はドラッグした範囲を埋めます。
- **ノーツを変換**は、チャート自身のノーツをフェイクスライダーまたはシャイニーの構造に変換します。
- **キアイ**は範囲をドラッグし、その中のすべてのタイミングポイントを1つのキアイ区間に変えます。

### 小節線ギミック

赤線から描かれるノーツです——ドンは対称な赤線1組、カッは3組で、各組は個別に設定できます。バーはノーツを中心に対称配置するか、後方に続けるかを選べます。赤線ツールには専用の設定可能なBPMがあり、関数ツールはミリ秒数またはビートグリッドを基準に、任意のBPMランプと選んだSVで範囲を赤線で埋めます。

### 構造ごとのSV

3つのオブジェクトレイヤー（チャート、フェイクスライダー、小節線）それぞれが専用のSVレイヤーを持ち、それぞれが自分自身の構造のミリ秒だけを扱います——3つが互いの緑線を表示することはもうありません。これらの内部でのコピー＆ペーストは、ミリ秒ではなくオブジェクトのインデックスでマッピングされるため、4本のフェイクスライダーから取り出したSVの形は、間隔がどうであれ次の4本にそのまま乗ります。振動SVが、ジェネレーターの7つのイージングカーブに加わりました。

## ファンシーアレンジャーページ

元のビジュアルアレンジャーで、挙動はそのままに、独自のタイムライン、タイミングバー、密度チャート、難易度セレクター、AR/CSコントロール、エクスポートボタンを備えた独立したページになりました。

### 変形

- テキスト
- 描画
- 数式
- 横
- 縦
- 太鼓
- 縦太鼓
- 円と楕円
- 四角形、三角形、ひし形
- 星
- らせん
- 無限大
- 円弧
- 直線
- 波とジグザグ
- ランダム
- ランダムウォーク
- DVDバウンド
- ピンホイール

一部の変形はチャンク分割、方向コントロール、シード付きランダム性、**往復**移動に対応しています。

折れ線とベジェ曲線は変形エンジン自体には存在しますが、まだインターフェイスからは選択できません。どちらも制御点を入力する手段が必要で、パラメータパネルにはまだそれがないためです。フリーハンドの形状は、当面**描画**でカバーされます。

### テキストパターン

次のようなテキストを入力します。

```text
67
TAIKO
日本
ภาษาไทย
```

テキスト変形は選択可能なシステムフォントを使い、結果をosu!のプレイフィールド内に収めます。テキストサイズ、余白、方向、ノーツ数、位置は結果を適用する前に調整できます。

テキストのノーツは上から下へ、各視覚的な行内では水平方向に並べられます。方向を反転しても上から下への順序は保たれ、各行内の水平方向の順序だけが反転します。

コンピューター上のフォントを選ぶこともできます！

### 描画パターン

描画は複数の独立したストロークを受け付け、人工的なパスにつなげるのではなく1つの視覚的な形状として扱います。画像をインポートしてストロークにトレースすることもできます。

描画のノーツは次のように並べられます。

1. 上から下へ
2. 各視覚的な行の中では左から右へ

方向を反転すると、上から下への順序は保たれ、各行が右から左に変わります。

描画ウィンドウのショートカット:

```text
Ctrl+Z    Undo the latest stroke
Ctrl+Y    Restore the latest undone stroke
```

### 数式パターン

> 警告: これはまだ実験的な機能です。いくつかの不具合が発生する可能性があります。

方程式モードは、グラフの輪郭からノーツのパスを生成できます。

対応モード:

- 陽関数、例: `y=sin(x)`
- 陰関数、例: `x^2+y^2=9`
- 媒介変数、例: `x(t)=cos(3*t)` と `y(t)=sin(2*t)`

陰関数・陽関数の式には制限を付け加えられます。例:

```text
tan(x^2+y^2)=1{|x|<3}{|y|<3}
```

内蔵のグラフキーボードは、次のようなグラフ関連の操作に特化しています。

```text
sin  cos  tan
asin acos atan
sqrt abs
exp ln log
floor ceil
pi e
```

方程式レンダラーが作るのは輪郭のみです。数式で表される領域を塗りつぶしたり色を付けたりはしません。

### ピンホイールパターン

ピンホイールは、湾曲したブレードと任意のシード付きゆらぎを持つ中心からのバーストを作ります。

コントロール:

- 内側円
- 内側円のノーツ数と半径
- ブレード数
- ブレードの曲率と広がり
- 内側と外側の半径
- 回転
- 半径の増加
- ゆらぎ強度とシード

### アレンジャーの操作手順

1. タイムライン上をドラッグしてセクションを選択するか、`Ctrl+A`でマップ全体を選択します。
2. **すべてのノーツ**または**ドン / カッを分割**を選び、続けて変形を選びます。
3. パラメータを調整するか、変形ビュー内でパターンを直接ドラッグします。分割モードでは、ドンをドラッグするとドンのパターンが、カッをドラッグするとカッのパターンが動きます。
4. **選択したノーツを変形**を押してセッションに反映します。`Ctrl+Z` / `Ctrl+Y`はここでも有効です。
5. 必要に応じて**AR**と**CS**を設定します——`0.00`から`10.00`まで`0.01`刻みのスライダーで、数値入力欄とピンク色の`+` / `-`ボタン（今ではアプリ内のすべてのスピンボックスと同様）が付いています。`AR 0.00`が最も遅いアプローチレートで、`CS 0.00`が最も大きいサークルサイズです。何もしなければ`ApproachRate:10`と`CircleSize:7`のままです。
6. **適用済み譜面をエクスポート**は、変形を適用した難易度を別ファイルとして書き出します。**すべての変更を元のファイルに適用**は、バックアップを取った上で読み込んだ`.osu`を上書きします。

変形ペインはプレビューです。エクスポートまたは適用するまで何も書き込まれません。

ビートマップの背景は変形ビューに表示され、不透明度を調整でき、別の画像をドラッグして差し替えることもできます。

## 保存とエクスポート

| 操作 | 場所 | 内容 |
|---|---|---|
| 保存 | グローバルヘッダー | 変更されたすべての難易度を、それぞれ先にバックアップを取ってから一度に書き込む |
| 新しい難易度をエクスポート | グローバルヘッダー | 同じ曲フォルダーに新しい難易度ファイルを書き込む |
| 適用済み譜面をエクスポート | ファンシーアレンジャー | 選択した保存先に、変形を適用した難易度を書き込む |
| すべての変更を元のファイルに適用 | ファンシーアレンジャー | バックアップを取った上で、読み込んだ`.osu`を上書きする |

保存すると`[TimingPoints]`と`[HitObjects]`が再生成され、それ以外のセクションはすべてそのまま引き継がれます。意図的に失われるのは、この2つのセクション内にある`//`コメントだけです。

## マッパー向けの重要な注意事項

### 必ずバックアップを取る

プログラムは上書き前にバックアップを取りますが、大切なビートマップは編集前に別途コピーを保管しておいてください。

### エクスポートした譜面をosu!でテストする

エクスポートした難易度は必ずosu!エディターで開き、次を確認してください。

- ノーツの位置とタイミング
- タイミングポイント、SV、小節線
- ヒットサウンド
- Approach RateとCircle Size
- 背景と難易度名

### 視覚的な読みやすさはノーツ数に左右される

テキスト、数式、描画、細かい形状は、認識可能な状態を保つために十分な数の選択ノーツを必要とします。パターンが不完全に見える場合は、次を試してください。

- 選択するノーツを増やす
- パターンあたりのノーツ数を増やす
- テキストを単純にする
- ピンホイールのブレード数を減らす
- 方程式の解像度を上げる
- グラフの範囲やサイズを調整する

### 既知の近似

このプログラムは`[Difficulty]`セクション自体の値をまだパースしないため、スライダーの長さはosu!既定の`SliderMultiplier`である1.4を使って計算されます。スライダーの**タイミング**は正確です。倍率を上書きしているマップでは、保存される長さの値だけがわずかにずれることがあります。

## ソースからのビルド

```text
pip install -r requirements-build.txt
pyside6-lrelease translations/taiko_ja.ts
python -m unittest discover
pyinstaller --noconfirm --clean TaikoFancyArranger.spec
```

ソースから実行するには`python gui.py`、Windowsでは`run_from_source.bat`を使います。

パッケージング関連ファイル:

| ファイル | 用途 |
|---|---|
| `VERSION` | ビルドに組み込まれるリリースバージョン |
| `TaikoFancyArranger.spec` | PyInstallerのspecファイル——`assets/`、`VERSION`、コンパイル済みの`.qm`翻訳をバンドルする |
| `requirements.txt` | ランタイム依存関係（PySide6） |
| `requirements-build.txt` | 上記に加えてPyInstaller |
| `.env.example` | 環境変数が**一切**不要であることを示すためのファイル。ここに秘密情報を置かないこと |
| `.github/workflows/release-windows.yml` | ポータブルZIPとSHA-256チェックサムをビルドし、公開されたリリースに添付する |

`vX.Y.Z`とタグ付けされたGitHubリリースを公開すると、そのワークフローが実行され、翻訳をコンパイルし、ビルドし、`TaikoFancyArranger-Windows-x64.zip`と`SHA256SUMS.txt`をアップロードします。対応する`docs/releases/vX.Y.Z.md`が存在する場合は、ZIPに同梱されます。

プログラムは環境変数を読み込まず、`.env`ファイルも必要としません。`.env`および鍵・証明書ファイルはgitignoreされています。

テストはヘッドレスで実行されます。

```text
QT_QPA_PLATFORM=offscreen python -m unittest discover -v
```
