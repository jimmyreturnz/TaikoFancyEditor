# Taiko Fancy Arranger v3.1.0

Updates arrive on their own, every toolbox gets rebindable keys, and a new layer owns kiai and note volume.

## New

### Auto-updater

The app checks GitHub Releases on startup, on a background thread, and offers anything newer than the running build. The download is verified against the SHA-256 published with the release and refused on a mismatch, then extracted into a **new folder beside the current one** — the copy you are running is never written to, so a failed update cannot leave you without a working app.

"Skip this version" stops it asking again for that release, and "Check for updates on startup" can be turned off in Settings, which also has a manual check.

### Kiai and Sound Volume layer

A seventh gimmick layer for kiai sections and note volume. It shows every timing point in the file from all layers at once — red for uninherited, green for inherited, yellow where both sit on the same millisecond.

The layer has nothing to do with scroll speed: its graph plots the volume in force over time, on a plain 0–100% axis, and it never writes a timing point. Kiai and Volume both act only on the lines already inside the dragged range — kiai drags snap to the current snap divisor, or to 1 ms with `Ctrl` held, and Volume runs the generator's easing curves and sweep/oscillate modes over each existing line's volume. Drag across a stretch with no timing point in it and nothing happens, by design: there is nowhere to put the flag, and inventing a green line to hold it is a scroll-speed edit made behind your back.

The Kiai tool has moved here from the fake slider layer. The layer is available as the gimmick page's seventh band and as a view in Add View.

### Rebindable toolbox keys

Every toolbox now has its own keys, listed under its own heading in Settings — the Editor page's, and one per gimmick layer. The same digit can drive the first tool of every toolbox because only one is ever reachable at a time.

### SV by red-line BPM

Layer 6's Function tool can restrict a generated sweep to red lines in a BPM interval — inclusive at both ends, so 500–1000 takes every red line from 500 to 1000 BPM, and setting both ends the same picks out exactly one. Both default to the BPM in force where the range starts. Everything outside the interval is left alone.

### Kiai that reads like a chorus

The kiai flash now starts the moment the playhead reaches the section and pulses once per measure from there, rather than on every beat from whatever timing point happened to govern the playhead. The fade spans the whole measure, so a slower BPM fades slower with nothing to configure. The lane itself takes a subtle white wash on the same pulse — far fainter than the note glow, since it covers the whole view rather than one circle. Shiny notes are a little brighter.

## Fixed

- **Slider ends were drawn at the wrong time.** Two separate causes: `SliderMultiplier` was hardcoded to 1.4 and `[Difficulty]` was never parsed at all, and the editor timeline read scroll velocity from the uninherited-only timing list, where every point reads as 1.0x — so SV never reached a drumroll's drawn end on *any* map. A 25.75px, 14-slide object at 223 BPM and `SliderMultiplier: 2.0` was ending 208 ms late.
- **Playback position is now smooth at every speed.** The playhead follows osu!(lazer)'s interpolating clock: it eases an eighth of the way toward the audio backend's reported position on every rendered frame, rather than absorbing a third of the whole error in one step at each report — and it can no longer travel backwards, which ordinary report jitter used to make it do several times a second. Changing speed also re-bases both clocks from the app's own continuous playhead, sampled before the rate changes; reading the backend's stale, whole-millisecond report there is what moved the playhead on every 25/50/75% click.
  Slow playback is still not fully accurate, and the cause is now measured rather than guessed: Qt's FFmpeg backend advances `position()` in fixed ~93 ms song-time steps, so at 0.25x the app gets one true reading every 351 ms of real time. No interpolation can fix a source that coarse. The Windows backend reports every 1 ms with no rate error but cannot decode Ogg — see `docs/DEVELOPMENT_PLAN.md` for the measurements and the plan.
- **The hitsound offset was applied in song time.** It compensates audio output latency, which is real time — so an offset tuned at 100% was four times too large at 25%. The error was `offset x (1 - rate)`: exactly zero at 100%, worst at the slowest speed. It is now scaled by the playback rate.
- **Buttons painted over their own labels.** Two causes: the pink `+` / `-` pair, on the Fancy Arranger page and in the difficulty controls, was 30px and 28px wide against 32px of their own padding, leaving negative room for the glyph; and every checkable button was pinned to a width measured in its *unchecked* font, so the bold weight it switches to when selected no longer fit. Button widths are now measured from the text they draw, in both weights.
- SV rates can be generated as low as 0.01x, matching what the timing-line and fake-slider dialogs already accepted.
- **"Continue Without Saving" now sticks.** It left the difficulty marked dirty, so the very next view or page change asked again. The prompt stays quiet until you actually edit something else.
- **A hidden spin-box row came back visible.** `pink_spin_buttons` wraps every spin box in a new container after the dialog is built, which un-hid any row hidden before the wrap — so the Volume dialog dropped its checkbox rows but kept showing a position offset that does nothing. The wrapper now carries the row's visibility across.
- **The cursor millisecond in the corner of a layer only moved when you clicked.** Both views repainted on a mouse move only while a placement tool was active, so in select mode the readout sat on whatever number the last repaint left there.
- Dragging a fake slider no longer drags the shiny note beside it, and vice versa.
- Red lines in the fake slider layer can be configured by double-clicking them, as in the other layers.
- Shiny notes and fake sliders can be placed big or small, with `Shift` for big, like ordinary don and kat.

## Changed

- Button labels are Title Case throughout.
- The deprecated "Gimmick Editor" view type is gone from Add View; the gimmick page replaced it in v3.0.0.
- The release build no longer runs the test suite — it was taking hours. Tests run locally instead, via `tools/run_tests.bat` or as part of `build_windows.bat`.
- The repository root is tidier: planning documents moved to `docs/`, release notes to `docs/releases/`.
