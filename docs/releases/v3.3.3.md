# Taiko Fancy Arranger v3.3.3

Fancy Arranger's Apply made to keep what it shows, copy/paste and red lines tightened in the gimmick editor, and the first measured cut to note placement on heavy gimmick maps.

## Fixed

- **Apply in Fancy Arranger keeps the notes where the canvas showed them.** After Apply the transformation was still selected on the same notes, so the next click — on the canvas, the timeline, any control — re-ran it from the positions it had just been applied to, with the drag offset already zeroed. On a transformation that lays notes out absolutely, like Text, that drew them back at the pre-drag layout while the committed ones sat elsewhere. What was just applied now *is* the preview for that selection and those settings, until either changes or you undo. Two neighbours of the same bug went with it: **a canvas drag with no transformation selected committed nothing**, because the drag was only added to notes the transformation had moved; and **a centred transformation (Pinwheel, Circle) with a drag applied twice as far as shown**, because a drag nudges Center X/Y as well as offsetting the notes, and both were counted.
- **Pasted fake sliders keep their offset from the snap.** A plain fake slider's own red line sits on the slider's millisecond rather than the snap, so copy had nothing on the snap to measure from and paste dropped the slider straight onto the playhead — 20000 instead of 20002. Each fake slider now counts the snap it was placed on, so a paste lands exactly where placing one there would. Don/Kat structures and shinies with their red line were already right.
- **A 1-tick anti-barline slit no longer leaves the last note without sheet after it.** The wall reached past an edge note by exactly its slit width, and a slit of one took the only tick that reach held. It now reaches half the slit plus one bar whenever that is more; at 2 ticks and up nothing changes.

## Changed

- **Placing a note on a heavy gimmick map is about 20% faster.** Every edit refreshes every gimmick layer, and each SV layer rebuilt its caches from the whole timing-point list even when a note placement had changed none of them. They now skip the rebuild when nothing they read has changed, judged from the points' own values so an in-place edit can never leave a layer stale. On a 21,040-timing-point, 4,671-object map: **192ms → 153ms per placement, undo 253ms → 206ms**. Fake slider placement is unchanged at about 270ms — it adds timing points, so its SV layers genuinely rebuild — and the four chart layers re-reading the document (68ms) are the next cost. Measured with the new `tools/measure_note_placement.py`.
- **Anti-barline slits default to 1 tick for Don and 2 for Kat**, down from the reference section's 2 and 4 — the same 1:2 ratio, narrower. The reference widths are one setting away in Config or Convert Notes.
- **The chart SV layer in the gimmick editor starts on the note** (offset 0). A -5ms lead-in is still the Editor page's default; in the gimmick editor the chart's SV sits against structures on exact milliseconds, so a lead-in is asked for.
- **Red Line refuses a millisecond that already has a red line, and says so** — "There is already a red line here." — a fake slider's or shiny's own line included. Two uninherited points on one millisecond are never placed; osu! reads only the first.

## New

- **Meter in a red line's double-click dialog.** Beats per bar, which is where that line's barlines fall; red lines only, since osu! reads meter from the uninherited point in force. The range runs to 10000 so an anti-barline line's deliberate 999 survives opening the dialog and pressing OK.
